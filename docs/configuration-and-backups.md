# Конфигурация и резервные копии

## Что хранить в Git

В Git хранится только обезличенный пример [VLESS + TCP + REALITY inbound](../examples/vless-reality-inbound.example.json). Все значения в угловых скобках — заполнители. Этот фрагмент показывает структуру и не является готовым файлом для запуска. На рабочем сервере конфигурацией управляет 3x-ui; его база `/etc/x-ui/x-ui.db` содержит учётные данные клиентов и параметры входов.

На сервере генерировать UUID и REALITY private key через 3x-ui/Xray. Не переносить рабочие UUID, private key, short ID, ссылки подписки или QR в шаблон, issues, коммиты и логи CI. Публичная часть ключа и клиентский профиль тоже не нужны в этом репозитории.

`.gitignore` игнорирует конфиги, JSON/YAML/TXT-файлы, базы, архивы и клиентские экспорты по умолчанию; примеры с суффиксом `.example` разрешены. Перед коммитом проверять `git status --ignored`, `git diff --cached` и список добавленных файлов. Игнорирование не защищает от `git add -f`.

## Резервная копия панели

База работает в режиме SQLite WAL, поэтому копировать только `x-ui.db` при работающей панели нельзя: последние изменения могут находиться в WAL-файле. Для простой согласованной копии остановить панель на время архивации. Это ненадолго прервёт VPN и веб-панель.

```sh
sudo install -d -o root -g root -m 700 /root/x-ui-backups
sudo bash -euc '
  set -o pipefail
  archive="/root/x-ui-backups/x-ui-$(date +%F-%H%M%S).tar.gz"
  systemctl stop x-ui
  trap "systemctl start x-ui" EXIT
  tar --numeric-owner -czf "$archive" /etc/x-ui
  chmod 600 "$archive"
  printf "Backup created: %s\\n" "$archive"
'
```

Архив содержит базу панели, клиентские UUID и другие секреты. Зашифровать его до копирования за пределы сервера; например, GPG запросит парольную фразу интерактивно:

```sh
gpg --symmetric --cipher-algo AES256 --output /root/x-ui-backups/x-ui-backup.tar.gz.gpg /root/x-ui-backups/x-ui-backup.tar.gz
```

Хранить зашифрованную копию и парольную фразу отдельно. Передавать архив в приватное хранилище, которое не синхронизируется с этим Git-репозиторием. Не использовать парольную фразу прямо в командной строке.

Перед удалением незашифрованного архива проверить, что зашифрованный файл читается: `gpg --decrypt --output /dev/null /root/x-ui-backups/x-ui-backup.tar.gz.gpg`. Затем удалить исходный архив обычным `rm`; не полагаться на `shred` на SSD или виртуальном диске.

## Восстановление панели

Восстанавливать на сервере с совместимой версией 3x-ui. Проверить доступ по SSH до начала работ и иметь копию текущего `/etc/x-ui` вне целевой директории.

```sh
sudo gpg --output /root/x-ui-restore.tar.gz --decrypt /secure/path/x-ui-backup.tar.gz.gpg
sudo chmod 600 /root/x-ui-restore.tar.gz
sudo systemctl stop x-ui
sudo mv /etc/x-ui "/etc/x-ui.before-restore-$(date +%F-%H%M%S)"
sudo tar --numeric-owner -xzf /root/x-ui-restore.tar.gz -C /
sudo systemctl start x-ui
sudo systemctl status x-ui --no-pager
```

После восстановления проверить вход в панель, слушающие порты и подключение тестового клиентского устройства. База из архива заменяет текущее состояние панели и возвращает значения на момент создания копии. Сначала убедиться, что распаковка завершилась успешно; если нет, вернуть каталог `x-ui.before-restore-*` на место.

## Границы этой копии

Архив `/etc/x-ui` сохраняет состояние панели, но не весь сервер. Отдельно документировать и защищённо резервировать Caddy/TLS, UFW, SSH и системные overrides, если требуется полный disaster recovery. Не собирать эти файлы в публичном репозитории: они могут содержать домены, пути панели, приватные TLS-ключи и правила доступа.
