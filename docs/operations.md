# Операционное руководство

Снимок состояния: 2026-10-26 (read-only проверка сервера и H2). Команды выполняются на VPN-сервере с правами root или через `sudo`. Перед любыми изменениями проверить текущие конфиги и иметь независимый SSH-доступ.

Для установки на чистый сервер использовать [пошаговый runbook развёртывания](deployment-runbook.md). Это руководство описывает уже работающую схему и её дальнейшее обслуживание.

## Сервисы и каталоги

| Назначение | Служба / путь |
|---|---|
| Панель и супервизор Xray | `x-ui.service` |
| Исполняемый файл панели | `/usr/local/x-ui/x-ui` |
| База и параметры панели | `/etc/x-ui/` |
| Бинарные файлы Xray и geo-файлы | `/usr/local/x-ui/bin/` |
| Журналы панели | `/var/log/x-ui/` |
| Веб-прокси и TLS | `caddy.service`, `/etc/caddy/Caddyfile` |
| Защита от перебора | `fail2ban.service`, `/etc/fail2ban/jail.d/` |
| Межсетевой экран | UFW |

Не копировать содержимое каталогов с настройками или базой в этот публичный репозиторий.

## Проверка состояния

```sh
systemctl status x-ui caddy fail2ban --no-pager
systemctl is-enabled x-ui caddy fail2ban apt-daily.timer apt-daily-upgrade.timer
ss -lntup
ufw status numbered
fail2ban-client status
```

У Xray может не быть отдельной активной systemd-службы: панель запускает дочерний процесс Xray. Проверяйте listener-порты и журнал `x-ui`, а не только `systemctl status xray`.

## Порты на снимке

| Порт | Назначение | Примечание |
|---:|---|---|
| TCP/22 | SSH | Вход root по ключу проверен; эффективно passwordauthentication=yes, требуется исправление |
| TCP/80 | Caddy / ACME HTTP-01 | Нужен для выпуска и продления сертификата |
| TCP/13198 | Рабочий VLESS + REALITY вход | Проверен HTTP-прокси H2; телефон проверить отдельно |
| TCP/443 | Прежний вход | Не слушается; правило UFW ещё разрешает порт |
| TCP/8443 | Веб-панель через Caddy | Ограничить источники доступа при возможности |
| TCP/19744 | Старый VPN-вход | Не слушается; правило UFW ещё разрешает порт |
| TCP/2053 | Backend панели | Loopback; внешнего разрешения UFW нет |
| TCP/2096 | Backend подписок | Wildcard listener; доступен через маршрут Caddy `/sub/*`, отдельного разрешения UFW нет |

Таблица отражает настроенный firewall; доступность снаружи зависит также от провайдера и сетевых фильтров.

## Обновление и перезапуск

1. Перед обновлением сохранить резервную копию `/etc/x-ui/` вне Git и ограничить права (`chmod 700` для каталога, `chmod 600` для файлов с секретами).
2. Записать текущую версию панели/Xray и проверить доступ к серверу по SSH.
3. Обновлять панель и Xray по отдельности, чтобы при регрессии можно было определить причину.
4. После изменения проверить `systemctl status x-ui caddy fail2ban`, `ss -lntup` и подключение тестовым клиентом.
5. Не перезагружать сервер, пока не проверен альтернативный SSH-доступ и не согласовано окно простоя.

На 2026-10-19 версия Xray закреплена на 26.7.28 после проблемы совместимости REALITY handshake с ранее проверенными мобильными клиентами на более новой версии. Перед следующим обновлением провести клиентскую проверку и подготовить план отката; не обновлять Xray автоматически без проверки профиля.

## Очистка прежних портов

На 26 октября 443 и 19744 не слушаются; действующий VPN — 13198. После подтверждения миграции всех клиентов проверить отсутствие старых inbound в панели, затем удалить ненужные разрешения:

```sh
sudo ufw delete allow 443/tcp
sudo ufw delete allow 19744/tcp
sudo ufw status numbered
sudo ss -lntup
```

Проверить удаление правил IPv4 и IPv6; отдельно убрать правила у провайдера. Не закрывать 443 на новом VDS, если именно на нём настроен VPN. После изменения проверить профиль TCP/13198. В рамках актуализации README правила не менялись.

## SSH, панель и подписки

Прежнее утверждение об отключённых SSH-паролях не соответствует проверке 26 октября: `sshd -T` показывает `permitrootlogin yes`, `passwordauthentication yes`. После проверки ключевого входа, sudo-администратора и консоли выполнить hardening по runbook. Не отключать единственный рабочий способ входа.

Caddy обслуживает Basic Auth и отдельную форму входа 3x-ui; пароли независимы. `/sub/*` проксируется на 2096, поэтому отсутствие разрешения UFW для 2096 не закрывает подписки через 8443. Определить необходимость маршрута и ограничений источников. Текущий Caddyfile не отключает TLS-ALPN challenge явно; при размещении VPN на 443 применить вариант HTTP-01 из runbook.

Панель имеет systemd drop-in `/etc/systemd/system/x-ui.service.d/10-xui-sandbox.conf`; перед обновлением сохранять `systemctl cat x-ui` приватно и проверять разрешённые записываемые пути. Полный drop-in в публичном репозитории не хранится.

## Перезагрузка после обновлений

На 2026-10-26 всё ещё присутствует `/var/run/reboot-required` с `libc6`. Согласовать окно, проверить backup, SSH и консоль, выполнить `sudo reboot`, затем проверить SSH, `x-ui`, Caddy, Fail2ban, APT timers и действующий профиль TCP/13198. Подтверждения выполнения reboot в этой проверке нет.

## Обработка секретов

Резервные копии панели, QR и клиентские ссылки содержат данные, позволяющие подключаться к VPN или управлять им. Хранить их отдельно от Git, передавать защищённым способом и менять затронутые ключи/пароли при подозрении на утечку. Если секрет когда-либо попал в Git, простого удаления файла недостаточно: считать его раскрытым и ротировать.
