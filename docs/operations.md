# Операционное руководство

Снимок состояния: 2026-10-19. Команды выполняются на VPN-сервере с правами root или через `sudo`. Перед любыми изменениями проверить текущие конфиги и иметь независимый SSH-доступ.

Для установки на чистый сервер использовать [пошаговый runbook развёртывания](deployment-runbook.md). Это руководство описывает уже работающую схему и её дальнейшее обслуживание.

## Сервисы и каталоги

| Назначение | Служба / путь |
|---|---|
| Панель и супервизор Xray | `x-ui.service` |
| Исполняемый файл панели | `/usr/local/x-ui/x-ui` |
| База и параметры панели | `/etc/x-ui/` |
| Бинарные файлы Xray и geo-файлы | `/usr/local/x-ui/bin/` |
| Журналы панели | `/var/log/x-ui/` |
| Веб-прокси и TLS | `caddy.service`, `/etc/caddy/Caddyfile` |
| Защита от перебора | `fail2ban.service`, `/etc/fail2ban/jail.d/` |
| Межсетевой экран | UFW |

Не копировать содержимое каталогов с настройками или базой в этот публичный репозиторий.

## Проверка состояния

```sh
systemctl status x-ui caddy fail2ban --no-pager
systemctl is-enabled x-ui caddy fail2ban apt-daily.timer apt-daily-upgrade.timer
ss -lntup
ufw status numbered
fail2ban-client status
```

У Xray может не быть отдельной активной systemd-службы: панель запускает дочерний процесс Xray. Проверяйте listener-порты и журнал `x-ui`, а не только `systemctl status xray`.

## Порты на снимке

| Порт | Назначение | Примечание |
|---:|---|---|
| TCP/22 | SSH | Только ключевая аутентификация для root |
| TCP/80 | Caddy / ACME HTTP-01 | Нужен для выпуска и продления сертификата |
| TCP/443 | Новый VLESS + REALITY вход | Профиль требуется проверить с клиентского устройства |
| TCP/8443 | Веб-панель через Caddy | Ограничить источники доступа при возможности |
| TCP/19744 | Старый VPN-вход | Временный резерв; удалить после подтверждения миграции клиентов |

Таблица отражает настроенный firewall; доступность снаружи зависит также от провайдера и сетевых фильтров.

## Обновление и перезапуск

1. Перед обновлением сохранить резервную копию `/etc/x-ui/` вне Git и ограничить права (`chmod 700` для каталога, `chmod 600` для файлов с секретами).
2. Записать текущую версию панели/Xray и проверить доступ к серверу по SSH.
3. Обновлять панель и Xray по отдельности, чтобы при регрессии можно было определить причину.
4. После изменения проверить `systemctl status x-ui caddy fail2ban`, `ss -lntup` и подключение тестовым клиентом.
5. Не перезагружать сервер, пока не проверен альтернативный SSH-доступ и не согласовано окно простоя.

На 2026-10-19 версия Xray закреплена на 26.7.28 после проблемы совместимости REALITY handshake с ранее проверенными мобильными клиентами на более новой версии. Перед следующим обновлением провести клиентскую проверку и подготовить план отката; не обновлять Xray автоматически без проверки профиля.

## Переход с резервного порта

После подтверждения TCP/443 на всех клиентах:

1. Удалить старый inbound из панели.
2. Удалить разрешение TCP/19744 из UFW для IPv4 и IPv6.
3. Убедиться, что TCP/19744 больше не слушается (`ss -lntup`).
4. Проверить основной профиль по TCP/443 после перезапуска Xray.

## Перезагрузка после обновлений

На снимке 2026-10-19 присутствовал `/var/run/reboot-required` из-за системного обновления, включавшего `libc6`. Запланировать короткое окно простоя, выполнить `reboot`, затем проверить SSH, `x-ui`, Caddy, Fail2ban и оба VPN-профиля.

## Обработка секретов

Резервные копии панели, QR и клиентские ссылки содержат данные, позволяющие подключаться к VPN или управлять им. Хранить их отдельно от Git, передавать защищённым способом и менять затронутые ключи/пароли при подозрении на утечку. Если секрет когда-либо попал в Git, простого удаления файла недостаточно: считать его раскрытым и ротировать.
